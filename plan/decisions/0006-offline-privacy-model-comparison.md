# ADR-0006 한국어 개인정보 탐지 후보의 분리 평가

> 상태: Accepted — 합성 입력의 로컬 비교만 진행. 운영 모델 채택은 아님
> 결정일: 2026-10-19

## Context

검사 Process의 종료·출력 검증과 별개로, 기존 spaCy 후보는 합성 12건 중 이름 누락·일반 문구 오탐·비표준 이메일 누락을 보였다. 실행 제어를 통과했다는 이유로 이 모델을 Main에 등록할 수 없다. 현재 실명 최소화·관계 보존 정책도 유지해야 한다.

## 검토한 선택지

- 기존 모델을 그대로 채택: 탐지 실패를 남긴 채 실제 외부 전송을 허용하므로 선택하지 않는다.
- 알려진 12건에 맞춰 이름 목록·예외를 추가: 평가 입력에 과적합하고 일반화를 확인할 수 없어 선택하지 않는다.
- 다른 한국어 개인정보 모델을 같은 기준으로 분리 평가: 운영 변경 없이 누락·오탐·실행 자원을 비교할 수 있어 선택한다.

## Final Decision

작은 KoELECTRA 개인정보 NER 후보를 별도 Docker 실험으로 평가한다. 고정 Revision·파일 SHA-256·SafeTensors만 사용하고 공개 Model Card의 출처·라이선스를 보존한다. 모델 Repository의 Code나 Pickle을 실행하지 않는다. 추론은 비Root·Network 차단·CPU/메모리 제한에서 합성 입력만 사용한다.

이전 12건의 원문·기대 범위·업무 사실 보존 조건을 변경하지 않는다. 모델은 제목·본문만 받고 정답은 추론 후 평가에서 사용한다. 비교 범위는 기존 PERSON·EMAIL·PHONE이며 다른 모델 Label은 탐지 건수로만 드러낸다. 새로운 보호 종류를 운영 계약에 조용히 추가하거나 모든 위치·기관을 지우지 않는다.

모델 고유의 말미 BIO Label은 별도 Decoder에서 검증한다. 잘못된 순서·위치·종류, 범위 충돌·입력 상한 초과를 임의로 고치거나 빈 정상 결과로 만들지 않는다. 관계 보존·문맥 판단의 미완료 계약을 위치 목록만으로 대신하지 않는다.

## Rationale

실행 제어·응답 계약·탐지 정확도를 따로 확인하며, 학습의 다음 배포 단계를 위한 후보 판단 근거를 얻는다. 모델이 공개한 자체 합성 성적을 우리 문의의 정확도로 사용하지 않는다. 동일한 기존 Dataset을 활용하는 개발 비교이지 독립적인 최종 평가가 아니다.

## Affected Files

- Lab: `experiments/privacy-ner/koelectra/`, 상위 `.dockerignore`와 실험 안내
- WIL: 후보 비교 보고서·10월 19일 노트·주간 계획
- 변경하지 않는 대상: Java Main·Bean·Worker 정책·Scanner JSON·DB Schema·AWS·배포 Image

## Follow-up Review

실제 결과의 누락·오탐·실행 실패와 메모리를 확인한 뒤 채택 여부를 판단한다. 단독 모델의 메모리 통과는 JVM·Worker를 합친 배포 사양의 근거가 아니다. 관계 보존과 별도 미확인 입력 평가, 전체 의존성 Hash Lock·License/Notice 정리, Linux Process 회수·Main 연결은 별도 Gate로 남긴다.
