# ADR-0003 — 실명 최소화와 사람 간 관계를 보존하는 전송 정책

> 상태: Accepted — 정책 승인. 관계 보존·문맥 판정의 실행 구현은 미완료
> 결정일: 2026-10-15
> 결정 책임자: 프로젝트 작성자
> 관련 자료: [개인정보 학습자료](../../week8-9/study-docs/privacy-detection-and-minimal-masking.md), [Week 8 계획](../../week8-9/weekly-plan.md)

## Context

문의의 요약·분류에 필요하지 않은 실명은 외부 전송에서 제외한다. 다만 모든 이름을 같은 표시로 바꾸면 다른 사람의 계정·주문이 노출된 사건에서 사람 간 관계가 사라질 수 있다. NER의 PERSON Label도 정확한 개인정보 판단을 보장하지 않는다.

사용자는 불필요한 실명은 가리되 사람 간 관계는 보존하고, `이메일`·`이매일`처럼 이름과 일반명사 양쪽으로 해석할 수 있어 문맥상 판단이 불분명한 표현은 일반명사로 해석하도록 승인했다.

## 검토한 선택지

| 선택지 | 장점 | 문제·위험 |
|---|---|---|
| NER의 모든 PERSON 범위를 같은 표시로 치환 | 처리 단순 | 일반명사 오탐과 인물 관계 손실 |
| 특정 문자열은 항상 이름에서 제외 | 일부 오탐 감소 | 실제로 그 이름을 가진 사람도 문맥과 무관하게 제외 |
| 문맥으로 이름을 판정하고 필요한 관계를 유지 | 업무 의미와 정보 최소화를 함께 유지 | 문맥·동일인 판단의 구현과 평가 필요, 모호한 실명 누락 가능 |

## Final Decision

### 전송 최소화와 관계 보존

DB의 접수 원문은 유지한다. 외부 AI가 업무를 수행하는 데 불필요한 실명은 전송용 복사본에서 치환한다. 영향 인원·마감·증상·복구 사실·요청은 보존한다. 이름이 등장했다는 이유만으로 같은 위험·같은 필요성을 가정하지 않는다.

```text
원문: 김철수 계정으로 로그인했는데 김영희의 주문이 보입니다.
목표: 사용자 A 계정으로 로그인했는데 사용자 B의 주문이 보입니다.
```

이 표시는 정책 설명용이며 아직 확정한 Scanner JSON 필드나 실행 Placeholder가 아니다. 한 문의에서 동일인임을 확인한 반복 지칭은 같은 표시로, 다른 사람임을 확인한 지칭은 다른 표시로 나타낸다. 이름 문자열이 같다는 사실만으로 동일인을 확정하거나 표기가 다르다는 사실만으로 다른 사람이라고 확정하지 않는다. 관계를 모르면 불확실성을 남기며 임의로 관계를 만들지 않는다.

실제 이름과 표시의 역변환 목록·실제 사용자 식별자는 외부 AI에 함께 보내지 않는다. 전역 영구 가명이나 새로운 개인정보 저장소를 만드는 결정은 아니다.

### 이름과 일반명사의 모호성

문맥상 이름인지 일반명사인지 불분명한 표현은 일반명사로 해석하여 PERSON 치환 대상에서 제외한다. `이메일`·`이매일` 문자열을 무조건 제외하는 예외 목록이 아니다. 이름이라는 명확한 문맥이 있다면 특이한 이름도 보호 대상으로 판단한다. NER Label 한 개만으로 모호한 문구를 확정하지 않는다.

| 문맥 예 | 정책상 해석 |
|---|---|
| `이메일이 도착하지 않습니다.` | 일반명사. PERSON 치환하지 않음 |
| `이매일 관련 문의입니다.`처럼 이름·오기 중 무엇인지 불분명 | 일반명사 쪽으로 해석. PERSON 치환하지 않음 |
| 문의자가 자기 이름이라고 명확히 밝힌 `이메일` | 이름이라는 문맥을 평가. 문자열 예외로 무조건 제외하지 않음 |
| `이메일 담당자 김철수에게 문의했습니다.` | 일반명사와 이름을 분리해 판단 |
| 실제 이메일 주소·전화번호·비밀번호 | 이름 모호성 규칙으로 기존 보호를 생략하지 않음 |

이 선택은 일부 실제 실명이 모호한 문맥에서 남을 수 있는 Trade-off를 가진다. 개인정보 부재나 익명화 완료를 보장하지 않는다. 실제 고객 정보의 외부 전송 근거·범위·보관 조건은 별도 검토 대상이다.

### 실패 처리 경계 유지

의미 판단에서 이름 여부가 모호한 것과 검사 실행·JSON·위치 검증이 실패한 것은 다르다. Timeout·미완료·계약 위반을 일반명사로 간주해 원문 전송을 허용하지 않는다. 기존 전송 중단·접수 원문 보존·현재 Attempt 확인·실패 저장 계약은 유지한다.

## Rationale

인명을 모두 지우는 것보다 문의 이해를 유지하면서 외부 전송을 최소화하는 것이 목적이다. 단순 예외 목록으로 우회하지 않고 문맥과 관계를 평가하며, 탐지 누락과 과도한 마스킹을 함께 측정한다.

## 구현 상태와 영향

현재 Java의 `SensitiveType.PERSON`·`[PERSON_REDACTED]`는 치환 종류만 제공한다. `DetectedSpan`과 Scanner JSON은 필드·시작·끝·종류만 가지므로 동일인 관계나 문맥 판정 근거를 표현하지 않는다. 현재 코드가 이 정책을 구현했다고 기록하지 않는다.

이번 변경은 정책·학습자료·진행 문서다. Java API·Scanner JSON·DB Migration·모델 Weight·고정 평가 Dataset·AWS·Image는 바꾸지 않는다. 앞선 12건 모델 평가를 새 정책으로 소급해 통과 처리하지 않는다.

## Validation과 Follow-up Review

- 사용자 승인과 기존 4필드 계약·단일 PERSON Placeholder를 대조했다. 정책의 실행 Test·실제 모델 재평가·Cloud 연결은 아직 미구현·미실행이다.
- 관계를 유지할 표현과 Scanner 계약의 Version·호환성을 정한 뒤 구현한다. 위치·종류만으로 관계를 추측하지 않는다.
- 명확한 이름·일반명사·모호한 표현·동명이인·반복 지칭·서로 다른 사람의 정보 노출을 각각 평가한다.
- 모호한 실명이 남을 위험은 실제 입력과 업무 목적에 맞춰 재검토한다.
- 독립적으로 가능한 배포 관측·복구 학습은 이어간다. 실제 AI 전송 전에는 입력 처리와 실행 제한을 검증한다.
