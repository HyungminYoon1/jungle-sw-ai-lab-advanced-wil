# ADR 0009 배포 검증과 개인정보 고도화의 분리

> 상태: Accepted
> 결정일: 2026-10-19
> 근거: 사용자의 V2·개인정보 모델 고도화 후속 분리와 배포 중심 계획 수정 승인

## Context

8–9주차의 목표는 기존 문의·AI 제안 흐름을 Cloud에 배포하고 실행 설정·관측·복구를 이해하는 것이다. 로컬 검사기의 실행 제어를 연결하던 중 탐지 모델 비교와 동명이인·동일인 관계 V2 설계로 범위가 확대됐다. V2는 독립 구조 검증·치환까지 구현했지만 Main에는 연결하지 않았고, 실제 모델 후보는 채택을 보류했다.

## 검토한 선택지

- V2와 모델 정확도 고도화를 모두 마친 뒤 배포 재개: 일반 입력 보호를 함께 준비하지만 배포 학습이 계속 지연된다.
- 개인정보 처리를 제거하고 임의 입력의 AI 활성화: 기존 보호·실패 차단 정책을 위반하므로 선택하지 않는다.
- 배포의 최소 실행 검증과 일반 입력 보호의 고도화를 분리: 합성 입력의 제한된 실험으로 배포를 학습하며 기존 정책과 후속 과업을 보존한다.

## Final Decision

세 번째 안을 선택한다. 인물 관계 V2의 Guard/Provider 연결, 추가 모델 비교·일반 정확도·관계 판단 개선을 후속으로 분리한다. 기존 코드·계약·실패 Case·모델 채택 보류는 유지한다. ADR 0003의 실명 최소화·관계 보존 정책이나 ADR 0007·0008의 독립 구현을 폐기하지 않는다.

현재 최소 선행 작업은 명시적인 실행 설정과 필수 의존성, Linux Process·Pipe·종료/Timeout 회수, 제한 자원의 동작 확인이다. 이후 전체 조립·Cloud 관측/비용·합성 전용 실제 AI·남은 DNS 비교·회귀·WIL을 진행한다. 이미 끝낸 전체 Snapshot 복원·Image Rollback은 반복하지 않는다.

실제 외부 AI 실험은 허용한 고정 합성 입력만 대상으로 분리한다. 입력 범위와 활성 구성을 강제한 별도 실험이어야 하며, 임의 입력을 빈 정상 검사로 통과시키는 Main 기본값을 두지 않는다. 기존 V1 JSON/위치 검증·Known Fragment Guard·실제 전송 Body 검사와 실패 시 전송 차단을 유지한다. 접수 원문·예약·현재 Attempt·처리 기한·자동 복구 차단 정책도 바꾸지 않는다.

통제된 응답으로 실행 제어를 검사한 결과는 탐지 모델의 정확도나 일반 개인정보 보호 완료가 아니다. 합성 배포 실험의 완료와 일반 입력의 AI 처리를 구분하며, 후자의 확대 전에는 후속 보호 과업을 다시 검토한다. 모델이 없는 실험 자원 수치로 향후 모델을 포함한 Task 사양을 확정하지 않는다.

AWS 변경·유료 AI·DNS·새 권한·삭제는 이번 계획 승인에 포함하지 않는다. 당일 입력·호출·비용 조건과 Cloud 변경 범위를 별도 확인한다. 취업 일정과 Project 주 6시간 상한은 유지하며 새로운 후속 날짜를 자동 배정하지 않는다.

## Rationale

학습의 중심과 실제 선행 의존성을 구분한다. 안전한 실패를 유지한 채 실행 환경의 문제부터 확인하고, 개인정보 고도화가 독립적으로 가능한 관측·DNS·비용·마감을 계속 막지 않게 한다. 배포 완료를 실제 고객 데이터 처리 준비 완료로 확대 해석하지 않는다.

## Affected Files

- WIL: 주간 계획의 현재 우선순위·후속 목록·변경 이력, V2 계약의 Deferred 안내와 이 결정
- Lab: 배포에 필요한 로컬 Linux 실행 재현 도구. 업무 계층·Main 활성화·DB Schema·V2/모델 구현은 변경하지 않음

## Follow-up Review

먼저 기존 Process Transport의 Linux 실행과 자원 회수를 검증한다. 합성 전용 전체 AI 구성은 허용 입력 강제·설정 누락 거부·비밀값 비출력·원문/실행권 보존을 확인한 뒤 실제 외부 호출 범위를 정한다. 일반 입력 확대나 후속 모델 채택은 별도 검토한다.
