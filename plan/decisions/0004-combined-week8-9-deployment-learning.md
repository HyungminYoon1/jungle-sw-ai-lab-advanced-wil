# ADR-0004 배포 학습을 8–9주차로 통합한다

> 상태: Accepted
> 결정일: 2026-10-17
> 대체 범위: ADR-0002의 기술 학습·취업 단계 주차 배치. 수직 깊이·수평 확장 제한과 완료 기준은 유지

## 배경

배포 학습은 처음에 10/8~10/12의 4일로 배정했지만, IAM·Private RDS·TLS·HTTPS·복원과 Image 호환성을 직접 확인하는 과정에서 9주차 기간까지 사용했다. 작성자는 실제 진도에 맞춰 학습 묶음과 디렉터리를 `week8-9`로 통합하고, 실제 17일에 이어진 실습도 16일 학습 회차에 기록하도록 요청했다. 10/17·10/18에는 새 학습을 배정하지 않고 10/19에 재개한다.

## 검토한 선택지

| 안 | 장점 | 문제 |
|---|---|---|
| 계속 Week 8 연장으로만 표시 | 기존 구조 유지 | 실제로 사용한 9주차와 취업 계획의 변화가 드러나지 않음 |
| Week 9에 별도 기술 주제를 신설 | 주차별 폴더 구분 | 같은 배포 학습을 인위적으로 나누고 새 범위를 추가하게 됨 |
| 같은 배포 학습을 Week 8–9로 통합 | 실제 기간과 하나의 학습 목표가 일치 | 취업 단계의 배치를 명시적으로 조정해야 함 |

## 결정과 이유

세 번째 안을 선택한다. `week8`의 자료를 `week8-9`로 옮기고 상대 링크·현재 계획을 함께 갱신한다. 날짜별 보고서와 기존 Image Tag·Source Commit·Script 이름은 실행 근거이므로 바꾸지 않는다.

기술 학습은 Week 1–7의 완료 기록과 Week 8–9의 배포 통합 과정으로 구성한다. 기존 Docker·CI·System·IAM·ECS/ECR·RDS·DNS/HTTPS·AI 연결·관측·복구·복습·WIL 범위는 줄이지 않는다. 디렉터리 이름 변경을 미완료 과업의 완료 처리로 사용하지 않는다.

12주 전체 틀은 유지한다. 기존 Week 9의 취업 Baseline·Portfolio 근거 정리는 Week 10의 맞춤 지원·면접 준비와 합치고, Week 11·12의 취업 과업은 뒤로 밀지 않는다. 지원·면접 일정은 기술 학습 마감을 기다리지 않는다.

기술 과업이 남으면 같은 통합 묶음의 잔여로 추적하되 취업 우선 기간의 Project 작업 주 6시간 상한 안에서 진행한다. 수직 마감 전까지는 핵심 코드를 이해·검증하는 방식을 유지하고 새 수평 기능은 시작하지 않는다. 마감 후의 AI 보조 수평 확장도 같은 상한을 공유하며 별도 6시간을 더하지 않는다. 추가 날짜·학습량 변경이 필요하면 실제 잔여량과 취업 일정을 보고 재조정한다.

## 기록과 일정

- 실제 10/17의 B→P 대조·psql 17·Process 관찰은 10/16 학습노트에 통합한다. 실행일 10/17의 보고서는 보존한다.
- 10/17·10/18은 휴무이며 새 학습·구현·평가를 배정하지 않는다.
- 10/19 월요일에는 메모리·Log의 남은 문답과 실행 상태·비용 확인부터 시작하고, 개인정보 처리·전체 AI 연결의 선행 구현을 이어간다. 남은 전체 분량을 하루에 마친다고 약속하지 않는다.
- Week 8–9 WIL은 같은 배포 학습의 계획 대비 결과와 이해 변화를 하나의 통합 회고로 정리한다.

## 영향 파일과 후속 확인

Root README, 총괄 계획·Roadmap·콘텐츠 계획·계획 안내, ADR-0002의 일정 안내, `week8-9/weekly-plan.md`·배포 계획·통합 학습노트와 경로 참조에 반영한다. 과거 계획 변경 기록은 당시 판단으로 보존한다.

19일 재개 때 취업 일정과 주간 가용시간을 먼저 확인해 작은 학습 Block을 배치한다. Gate에서 설명·직접 수정·실제 실행 결과를 다시 확인한다. Cloud 실행·유료 AI·권한·삭제 승인은 확대하지 않으며, 휴무 일정만으로 실제 리소스가 중지됐다고 기록하지 않는다.
