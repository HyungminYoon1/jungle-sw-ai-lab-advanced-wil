# ADR 0007 인물 관계 V2의 독립 구조 검증

> 상태: Accepted — 로컬 독립 검증기 범위. 치환·전송·운영 조립은 포함하지 않음
> 결정일: 2026-10-19
> 근거: 인물 관계·문의 간 연결 금지와 명시적 판단 보류 보존·관계 누락 거부의 문답, 이어서 구현 요청

## Context

기존 V1은 개인정보 위치·종류만 담으며 인물 관계를 표현하지 않는다. 같은 이름을 같은 사람으로 묶거나 다른 등장 번호를 모두 다른 사람으로 해석하면 승인한 관계 보존 정책을 위반한다. 실제 모델 후보도 아직 채택하지 않았다.

## 검토한 선택지

- 기존 V1에 선택 필드 추가: 누락을 예전 정상 응답과 혼동하고 Version을 구분하기 어렵다.
- V2 검증·치환·Provider·Main을 한 번에 변경: 검토 중인 표시와 입력 표현까지 먼저 확정하게 된다.
- 별도 V2 구조 검증기부터 구현: V1과 운영 흐름을 유지하며 누락·모순 거부를 검증할 수 있다.

## Final Decision

세 번째 안으로 `AiPrivacyScanResultV2Validator`를 추가한다. 직접 생성하는 검증기이며 Bean·자동 Version 선택·실제 모델은 등록하지 않는다. 명시적인 Version 2·완료·위치·전체 관계표를 요구하고 기존 고정 `InvalidScanResultException`을 사용한다.

등장 번호는 원문의 Title 다음 Body 위치 순서로 한 호출 안에서만 정한다. 같은 위치의 완전히 같은 중복만 제거하고 다른 위치에 같은 번호를 쓰거나 겹친 범위·종류·번호가 충돌하면 거부한다. 원시 항목 개수 상한은 중복 제거 전 적용한다.

각 PERSON 쌍에 SAME·DIFFERENT·UNDETERMINED 하나씩을 요구한다. 누락을 판단 보류로 채우지 않고, SAME의 추이 관계와 같은 사람의 제3자 관계가 최종 표에서 일관돼야 한다. SAME 집합과 집합 사이의 판정이 충돌하면 거부한다. DIFFERENT는 추이적으로 확장하지 않는다. 쌍 방향·순서만 정규화하며 의미 값은 수정하지 않는다.

응답 Byte·Span·관계 개수 상한을 명시한다. 관계 상한 0은 PERSON 0~1개만 허용하는 설정으로 둔다. N개의 관계 개수는 long으로 계산하고 상한·실제 배열 개수를 확인한 뒤 Pair Map을 만든다. N×N 행렬이나 전체 삼중 반복은 만들지 않는다. SAME 집합 확인은 반복문과 경로 압축으로 처리해 재귀 호출을 피한다.

결과는 원문·JSON 없는 불변 메타데이터다. 결과와 구성 항목의 `toString()`도 내용·참조를 숨긴다. 검증 결과가 원문의 실제 관계와 맞는지는 별도 모델 평가 대상이다.

## Rationale

승인한 의미 보존 정책의 구조적 조건부터 구현하며 현재 전송 경로의 V1을 바꾸지 않는다. 의미 판단을 했지만 어렵다고 보고한 결과와 계약 자체를 지키지 않은 응답을 분리하고, 관계를 임의 복구해 새 사실을 만들지 않는다.

## Affected Files

- Lab: 새 V2 검증기·Test와 README 안내. 기존 V1·Preparer·Guard·Controller·Service·Repository·DB·Worker 정책은 변경하지 않음
- WIL: V2 계약 초안·이 결정·검증 보고서·10월 19일 노트·개인정보 학습자료·주간 계획

## Validation과 Follow-up Review

Lab `ca37e69`에서 V2 172개와 기존 7개 Class를 포함한 핵심 402개가 통과했다. 기존 PostgreSQL Pipeline 20개는 V1 회귀이며 V2→DB 연결이 아니다. 명확한 동명이인을 SAME으로 잘못 보고했어도 구조가 일관되면 통과할 수 있음을 Test로 명시했다.

다음에는 미확인 관계를 유지하는 치환·표시 충돌·동일 원문과 결과 결합·Guard·실제 전송 형식을 검토한다. 실제 모델의 관계 정확도, Linux 실행/회수·전체 자원·Main 연결을 이 단독 검증으로 대신하지 않는다. 운영 상한과 외부 전송 구조도 자동 확정하지 않는다.
