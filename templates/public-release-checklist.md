# 공개 산출물 Checklist

> 대상 주차: Week <주차>  
> 검토일: <YYYY-MM-DD>  
> 검토 대상: <파일 또는 PR Link>

모든 항목을 확인한 뒤 공개한다. 확인하지 못한 항목은 이유와 후속 조치를 기록한다.

## Secret과 개인정보

- [ ] Secret, Token, Credential, Cookie, Session ID와 환경 변수 값이 없다.
- [ ] .env 파일 내용이나 Secret이 포함된 명령 출력이 없다.
- [ ] 개인정보, 비공개 대화 원문과 동의받지 않은 사용자 데이터가 없다.
- [ ] Log, Trace, Screenshot와 Dataset의 민감 값을 Redact했다.
- [ ] 내부 URL, IP, 계정 ID와 접근 가능한 임시 Link가 없다.

## 로컬·내부 Context

- [ ] Windows Drive를 포함한 로컬 절대 경로가 없다.
- [ ] 사용자와 AI 사이의 대화 맥락 없이 문서를 이해할 수 있다.
- [ ] 비공개 작업 Note와 개인 일정이 포함되지 않았다.
- [ ] Repository 내부 Link는 상대 경로이며 실제 대상을 가리킨다.

## 기술 정확성

- [ ] Version과 실행 환경이 표시되어 있다.
- [ ] Code, 설정, 명령과 API 예제가 실제로 검증되었다.
- [ ] 직접 학습·실행한 범위, 부분 확인과 계획만 있는 범위를 구분했다.
- [ ] 미실행 Test와 실패 결과를 숨기지 않았다.
- [ ] 문서의 질문·조건·설명과 실제 실행 결과가 일치한다.
- [ ] 외부 Library와 Service 동작은 공식 문서 또는 1차 자료로 확인했다.

## 주장과 증거

- [ ] 성능, 비용, 품질과 생산성 주장은 측정 조건과 원본 근거가 있다.
- [ ] 작은 Dataset이나 통제 환경의 결과를 일반화하지 않았다.
- [ ] 그래프와 표에 단위, 표본 수와 측정 조건이 있다.
- [ ] 사용자 Feedback은 참가자 수와 방식이 표시되어 있다.
- [ ] 실패, 한계와 다음 검증 항목을 포함했다.

## AI 활용과 기여

- [ ] AI가 보조한 부분과 학습자가 판단·수정·검증한 부분을 구분했다.
- [ ] 사전 자동화 Prototype 결과를 해당 주차의 성과로 계산하지 않았다.
- [ ] AI가 제시한 사실, 출처, Code와 Version을 다시 확인했다.
- [ ] 설명하거나 수정하거나 Test할 수 없는 생성 Code를 성과로 제시하지 않았다.

## 저작권과 공개 품질

- [ ] 외부 Code, 이미지, Dataset과 인용문의 License·출처를 확인했다.
- [ ] 긴 원문 복사 대신 필요한 내용을 직접 설명하고 적절히 인용했다.
- [ ] Placeholder, 임시 문구, 깨진 문자와 사용하지 않는 Section을 정리했다.
- [ ] Markdown Heading, Table, Link와 Image가 정상적으로 표시된다.
- [ ] 문서 제목, 요약과 파일명이 내용을 정확히 설명한다.
- [ ] UTF-8과 Repository의 줄바꿈 규칙을 지켰다.
