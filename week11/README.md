# Week 11 고객 후속 대화 정책과 학습 기록

> 시작일: 2026-10-27
> 상태: In Progress. 10/27 F01/F02/F04/F07/F11 합의 보존. 남은 검토/구현은 11/3~9의 Week 12로 이월
> 상위 기준: 취업 우선, 기술 과업 주 6시간과 전체 12주 일정 유지

기존 공식 답변과 배정/인계의 V10을 기준으로 고객 후속 메시지의 정책을 검토한다. 문의 등록자가 같은 Ticket에 추가 내용을 남기고 담당자가 새 글을 확인하는 흐름이 첫 설계 대상이다. 상태 API와 실제 운영 전체를 이번 주에 모두 구현하는 계획은 아니다.

11/3 작성자가 학회 참석으로 이어서 진행하지 못한 학습과 구현을 [12주차 계획](../week12/weekly-plan.md)에 반영하도록 요청했다. 이 기록과 확정한 정책은 유지하고, 다음 선택과 신규 구현은 12주차에서 계속한다. 날짜별 실제 활동이나 사용 시간을 보충해 추정하지 않는다.

## 문서와 읽는 순서

1. [정책 검토](./customer-followup-policy-review.md)에서 10/27의 다섯 합의와 11/3에 추가 합의한 F03/F05/F12를 확인한다.
2. 12주차에서는 F13의 Ticket 단위 작성과 공개 대화 활동 시각도 합의했다. [기술 계약](../week12/customer-followup-contract-draft.md)으로 이어가며 이미 합의한 작성 허용 상태, 새 글 정정, 명시적 확인과 목록 포함 여부는 다시 질문하지 않는다.
3. 선택한 정책을 Schema/API/실패 사례로 구체화한 뒤 작은 단위로 구현한다.
4. 상태 API와 실제 운영 정책은 해당 구현/출시 시점에 검토하고 기능 완료와 혼동하지 않는다.

- [실사용 설계](../plan/helpdesk-operational-design-draft.md): 기존 O1~O6과 10/27 고객 후속 합의
- [후속 목표 결정 기록](../plan/decisions/0012-helpdesk-operational-target.md): 목적, 선택지, 합의와 후속 검토
- [배정과 인계 확정 설계](../week10/ticket-assignment-contract-draft.md): 유지할 데이터/권한/Commit 경계
- [10/24 구현 및 원격 CI 근거](../week10/lab-reports/2026-10-24-ticket-assignment-lab.md): 새 실험과 구분할 기존 실행 결과
- [상위 Roadmap](../plan/weekly-roadmap.md#11주차--면접과제-대응과-취약-개념-재학습): 취업 및 취약 개념 보완 우선

## 10/27에 확정한 범위

- F01: 고객 후속 메시지는 Ticket 등록자 본인만 작성한다.
- F02: 첫 구현에서는 후속 메시지 때문에 AI를 자동 재호출하지 않는다. 기존 제안은 최초 문의 기준임을 표시한다.
- F04: 기존 세 상태에서 후속 작성을 허용하고 메시지 저장만으로 상태를 변경하지 않는다. 재개 규칙은 별도로 검토한다.
- F07: 본문 덮어쓰기/일반 삭제 대신 새 글로 정정하며 민감 정보 가림/삭제는 별도 예외 절차로 둔다.
- F11: 첫 구현에 현재 담당자의 명시적 확인을 포함한다. 조회로 자동 확인하지 않고 확인 지점과 인계 경계를 구분한다.
- 나머지 F/T/R 항목은 검토안이며 전체 목록의 작성이 일괄 승인이나 구현 완료를 뜻하지 않는다.
- 11/3에 다음 작업일을 11/3~9 모두 학습으로 배분했다. 실제 사용 시간은 별도로 기록하며 10/26의 미기록 활동이나 소요 시간을 추정하지 않는다.

주간 학습 및 구현 기록은 유지하고 10~12주차 블로그만 통합한다. 필요할 때 Study Note와 실행 보고서를 추가하되 정책 조사를 Test나 독립 구현의 근거로 계산하지 않는다. 고객 후속 기능의 정책 합의는 Cloud 재배포나 일반 입력 AI 활성화의 승인이 아니다.
